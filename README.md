# 高德 POI 采集器

按「关键词 × 地区」从高德地图采集 POI（商户名称、电话、地址、经纬度、评分），导出 CSV / JSON / XLSX。

既能装进 Agent 的技能目录、用一句自然语言触发，也能在命令行直接跑——两条路径共用同一套代码，没有第二份实现。

> **服务范围**：高德 POI 服务仅覆盖中国大陆。港澳台及境外未验证。
>
> 非官方工具，与高德地图无隶属或背书关系；不内置 Key，也不含任何高德数据（详见文末[许可与声明](#许可与声明)）。

---

## 与高德官方 skill 的区别

高德开放平台自己也发布了一个 Agent skill：[`AMap-Web/amap-lbs-skill`](https://github.com/AMap-Web/amap-lbs-skill)（MIT，Node.js）。**两者不是竞争关系，是两种用途**：

| | 官方 `amap-lbs-skill` | 本项目 |
|---|---|---|
| 定位 | 地图能力的对话入口：问一句、看一眼、给个链接 | 批量采集工具：跑一次、落成文件、可核对 |
| 输出 | 终端里的对话文本，或一个地图链接 | CSV / JSON / XLSX + 机器可读的运行报告 |
| 分页 | 一次一页，打印「第 x/y 页」让你再敲命令 | 翻到返回 0 条为止，自动翻完 |
| 依赖 | Node.js + axios | 只需 Python 3.6+，零三方依赖 |
| 能力范围 | 搜索、周边、热力图、路线、旅游规划 | **只做 POI 采集**，不做其他 API |

如果你只是想在对话框里问「附近有什么」，用官方那个就够了。如果你要的是「把这个城市这类商家的名单导成一张表，并且知道这份表全不全」，用这个。

> 一个具体差异值得提：官方那个用 `Math.ceil(count / offset)` 推算总页数。交互场景下无害，但批量采集会让使用者误以为数据完整——实测海口「汽修厂」`count=552`，实际只能取到 225 条。本项目不推算页数，只认「本页返回 0 条」。详见 [`references/api-notes.md`](references/api-notes.md)。

## 使用前提

**1. 一个高德「Web服务」类型的 Key**

申请路径：**高德开放平台 <https://lbs.amap.com/> → 控制台 → 应用管理 → 创建新应用 → 添加 Key → 服务平台选「Web服务」**。

服务平台**必须选「Web服务」**，不是「Web端(JS API)」——选错会得到 `10009`，且错误信息不会告诉你选错了。需要实名认证。详细步骤见 [`references/key-setup.md`](references/key-setup.md)。

Key 是你的账号身份和配额主体，请只用自己的，不要共用或转售他人 Key。

**2. Python 3.6+**

只用标准库，**不需要 `pip install`**。唯一可选依赖是 `openpyxl`——只在导出 `xlsx` 时需要，没装会自动降级成 CSV。

## 快速开始

### 1. 装进 Agent（推荐）

```bash
git clone https://github.com/znnnk/amap-poi-collector-skill.git
cd amap-poi-collector-skill
export AMAP_KEY=你的32位key        # 或 cp config.example.json config.json 后填写

# 把整个仓库挂进技能目录，目录名必须与 SKILL.md 里的 name 完全一致
ln -s "$PWD" ~/.dsh/skills/amap-poi-collector-skill      # Linux / macOS
```

Windows 在 cmd 里建目录联接（不需要管理员权限）：

```bat
mklink /J "%USERPROFILE%\.dsh\skills\amap-poi-collector-skill" "C:\path\to\amap-poi-collector-skill"
```

也可以直接把仓库克隆到 `~/.dsh/skills/amap-poi-collector-skill`，省掉建链接这一步。

### 2. 先验证一次

```bash
py scripts/collect.py -k 汽修厂 -r 文昌市 --dry-run
```

`--dry-run` 只打印计划、不发请求，用来确认 Key 和参数都没问题。

### 3. 然后直接说一句话

```
用户：帮我抓海口市的汽修厂名单

Agent：这次要跑 1 个单元（关键词「汽修厂」× 地区「海口市」），
       预计约 10 次请求。海口数据量较大，单次查询最多只能取回
       200 多条，可能会不完整。要继续吗？

用户：继续

Agent：跑完了。导出 output/amap_poi_20261108_101530.csv，共 223 条。
       按 POI ID 去重，电话空缺约 20%。注意：本次触顶了，
       本地实际有 551 条，只取回 223 条——要更全的话建议按区县分开抓。
```

Agent 会读 [`SKILL.md`](SKILL.md)：追问缺失的参数 → 报预算 → 等你确认 → 正式跑 → 按退出码分流汇报。它不会自己猜关键词，也不会在没告知你的情况下开始消耗配额。

### 4. 不装 Agent 也能用

```bash
py scripts/collect.py -k 汽修厂 -r 海口市 --yes --report-json output/report.json
```

Windows 上 `py` 是 Python 启动器，其他平台用 `python3`。

> **工作目录提醒**：`scripts/collect.py` 里的 `scripts/` 是相对**当前工作目录**的。在别的目录执行请用绝对路径。Key 不受影响——`config.json` 找不到时会回退到技能目录再找一次。

## 功能说明

| 能力 | 说明 |
|---|---|
| 关键词搜索 | 一个或多个关键词，`-k 汽修厂 -k 汽车维修` |
| 地区 | 省名 / 城市名 / **6 位 adcode**，可多个 |
| 组合执行 | 单元数 = 关键词数 × 地区数，顺序跑完 |
| 去重 | 按 POI ID 全局去重；同一条被多个关键词命中时，「命中关键词」列合并为 `汽修厂;汽车维修` |
| 导出 | CSV（默认）/ JSON / XLSX |
| 运行报告 | `--report-json` 输出机器可读回执，含每个单元的状态、请求数、是否触顶 |
| 错误处理 | 按 `infocode` 分三档：致命（立即中止）/ 可重试（指数退避）/ 跳过当前单元 |

**不包含**：GUI、地理编码、路线规划、周边搜索、百度 / 腾讯等其他数据源、自动按区县递归拆分、港澳台及境外。

## 参数与产物

### 参数

只有两个必填，其余全部有默认值。

| 参数 | 必填 | 说明 | 默认 |
|---|---|---|---|
| `-k` / `--keyword` | ✅ | 找什么，可重复 | 无 |
| `-r` / `--region` | ✅ | 城市名 / 省名 / 6 位 adcode，可重复 | 无 |
| `-n` / `--max-records` | | 本次总条数上限。单查询本身约 200 多条就到顶，通常没必要设 | 0（不限） |
| `-f` / `--format` | | `csv` / `json` / `xlsx` | `csv` |
| `-o` / `--output` | | 单个输出文件路径 | `<out-dir>/amap_poi_<时间戳>.<格式>` |
| `--report-json` | | 另写一份运行报告 | 不写 |
| `--max-requests` | | 请求数硬刹车 | 0（不限） |
| `--interval` | | 两次请求间隔（秒） | 0.4 |
| `--config` / `--out-dir` | | Key 文件路径 / 产物目录 | `config.json` / `output` |
| `--dry-run` / `--yes` | | 只打印计划不发请求 / 跳过执行前确认 | — |

完整列表见 `py scripts/collect.py --help`。

### 输出字段（19 列，固定顺序）

```
名称 电话 地址 省 城市 区县 行政区编码 分类 分类编码 经度 纬度
标签 商圈 网站 邮箱 评分 营业时间 命中关键词 POI ID
```

CSV 用 `utf-8-sig` 编码，Excel / WPS 双击打开不乱码。字段是可用的全量，没有「只导出电话」这类开关。

### 三种格式

装的是同一批数据，区别只在容器：

| `-f` | 内容 | 适合 |
|---|---|---|
| `csv` | 19 列，`utf-8-sig` | Excel / WPS / 数据透视 |
| `json` | `records` + `params` + `totals` + `units` + `errors` + `hit_cap_units` | 给程序读，能判定「这次完不完整」 |
| `xlsx` | `POI`（冻结首行、列宽已调）+ `运行摘要` 两个 sheet | 直接发给不用命令行的人 |

`xlsx` 在没装 `openpyxl` 时会**自动降级成同名 `.csv` 并返回那个路径**，不抛异常——所以判断产物要以 `--report-json` 里的 `outputs` 为准，不要按 `-o` 猜。

> 产物含真实商户电话，`output/` 已在 `.gitignore` 中，永不入库。

## 目录结构

仓库根目录**就是技能目录**（能直接 `ln -s` / `mklink` 到 `~/.dsh/skills/`），没有 `src/`、没有 `setup.py`、没有打包配置——少一层结构，Agent 少一个找不到文件的理由。

```
amap-poi-collector-skill/      # ← 技能目录，目录名必须与 SKILL.md 的 name 一致
├── SKILL.md                   # 门面：Agent 读它决定怎么问、怎么跑、怎么汇报
├── README.md                  # 本文件
├── SECURITY.md                # Key 泄漏处置、issue 里别贴什么
├── LICENSE  .gitignore  config.example.json
├── scripts/
│   ├── collect.py             # 单行入口：python scripts/collect.py ...
│   └── amap_poi/              # 引擎：cli / client / collect / export / normalize / report
├── references/                # SKILL.md 的附属文档：api-notes / error-codes / key-setup
└── samples/sample.csv         # 人工构造的假数据（不从真实数据抽样）
```

分层原则：`client` 只管 HTTP 与错误码，`normalize` 只管字段形状，`collect` 只管编排，`export` 只管落盘，`cli` 只管参数与退出码。**每一层都能单独 import 测试，不需要网络。**

> 单元测试在开发者本地运行，**不随仓库发布**（`scripts/tests/` 已列入 `.gitignore`）。

## 数据为什么可能不完整（重要）

这是本项目最需要提前知道的一件事。

### 单次查询有天花板，约 200~225 条

高德单次查询的返回量有上限，且**不固定**——随 `offset` 和查询本身漂移：

| 查询 | `offset` | 取到条数 | 下一页 |
|---|---|---|---|
| 汽修厂 @ 海口市 | 25 / 20 / 10 | **225 / 220 / 210** | 分别第 10 / 12 / 22 页空 |
| 汽修厂 @ 成都市 | 25 / 10 | **200 / 200** | 第 9 / 21 页空 |
| 汽修厂 @ 文昌市 | 25 | **106** | `count=108`，数据本身就这么少 |

由此确立三条规则：

1. **不存在「第 201 条一定空」**，天花板会漂移。
2. **只能靠「本页返回 0 条」判断到底**，不能按页数停，也不能按 `count` 算页数。
3. **`count` 不可信**。海口 `count=551` 只取到 225，成都 `count=572` 只取到 200。它只能当「这里数据多」的弱提示。

所以工具的判断是**启发式警告**：某个单元取到 200 条及以上就提示「疑似触顶」，此时退出码为 `2`，报告里 `hit_cap` 为 `true`。它可能误报（数据恰好 200 条且确实取全了），但不会漏报。

> **这不是工具截断的。** `-n / --max-records` 默认就是 `0`（不限），代码里也没有任何「到 200 就停」的分支——唯一的终止条件是「本页返回 0 条」。用 `-n 0` 显式不限跑海口「汽修厂」，得到的仍然是 **225 条 / 10 次请求**：前 9 页各 25 条，第 10 页服务端返回 0 条，循环就在这里结束。上限在服务端，不在本地。

### 区县名必须换成 6 位 adcode

| 输入 | 处理 |
|---|---|
| 省名 / 城市名（`海南省` / `海口市`） | 直接用 |
| 6 位 adcode（`460106`） | 直接用，**区县查询的唯一可靠方式** |
| 区县名（`龙华区`） | **直接拒绝**——实测被静默解析成**深圳**的龙华区，返回了错误地区的数据 |
| 其他 / 模糊 | 报错并提示给城市名或 adcode，**不猜** |

转 adcode 需要地理编码接口，不在本工具范围内。adcode 可在[高德行政区划查询](https://lbs.amap.com/api/webservice/guide/api/district)或公开区划表里查。

### 拆细范围能多拿约 60%

天花板是按「**一次查询**」算的，所以换一个更窄的范围，就等于换一个新的窗口。实测「汽修厂」在海口：

| 查询 | `count` | 去重后条数 |
|---|---|---|
| 海口市整城 | 547 | **223**（触顶） |
| 460105 秀英区 / 460106 龙华区 / 460107 琼山区 / 460108 美兰区 | 200 / 163 / 99 / 123 | 192 / 157 / 92 / 115 |
| 四区并集 | — | **556** |

**整城漏掉 333 条，占四区并集的 60%。**

这不是「突破平台限制」——平台限制的是单次查询的翻页深度，不是账号总取量。把过大的查询拆成多个合法查询是正常做法，但工具**不会自动拆**：请求量会成倍增长（一个城市可能拆成几十个子任务），必须你知情后才执行。

**所以看到「触顶」时，推荐动作是**：换更细的行政区（6 位 adcode）重跑，或补充同义关键词（`汽修厂` + `汽车维修`）提高召回。

## 常见问题

**Q：提示 `10009` / key 与平台不匹配？**
A：Key 的服务平台选错了，必须是「Web服务」。只能删掉重建，改不了。

**Q：提示 key 无效或配额耗尽？**
A：退出码为 `3`，工具不会把半成品当「完成」给你。如果是日配额（`10003` / `10044`），次日恢复；如果是 key 失效，到控制台检查或重建。

**Q：只拿到 200 多条，是我用错了吗？**
A：不是，这是平台的单查询上限，见上节。要更全就按区县拆开跑。注意旧脚本里当年那批「每份正好 200 条」的 CSV 是另一回事——那是旧脚本自己设了 `--max-records 200`，不是平台截断的。

**Q：为什么「龙华区」这样的区县名不被接受？**
A：同名区县会串，实测被解析到了深圳。请给 6 位 adcode。

**Q：电话那一列空了很多？**
A：部分 POI 本身就没登记电话（单次抽样 25 条里 23 条有电话）。`report.json` 的 `totals.tel_empty_rate` 是本次实际空缺率。

**Q：`-f xlsx` 没生成 xlsx，只多了个 csv？**
A：没装 `openpyxl`，已自动降级。`pip install openpyxl` 后重跑。

**Q：能抓港澳台或境外吗？**
A：不能。高德 POI 只覆盖中国大陆，境外请求的实际返回行为本项目**未实测**。

**Q：直接用 AI 拼 HTTP 请求不行吗？**
A：不行。参数易错、无法分页、无法统一限速、错误码会被静默当成「查无结果」——这正是本项目存在的理由。

## 合规与安全

- 不要把 Key 写进命令行参数、issue、截图或提交记录。发现泄漏请立刻到控制台**删除该 Key**（改 IP 白名单不够）。
- 采集结果里的商户名称、电话、地址属于个人信息 / 商业信息，受《个人信息保护法》《数据安全法》等约束。本工具只负责「按你给的参数取回平台公开返回的内容」，**不为你的用途背书**。
- 明确不建议、也不支持的用途：未经同意的电话营销与短信推送、转售或再分发数据集、绕过平台配额的大规模抓取。
- 公开演示、写文章、提 issue 时**不要贴真实采集结果**，请用 `samples/sample.csv`。
- 本项目遵循平台约束：单次返回量由平台决定，工具只做「翻到没有为止 + 如实报告」，**不实现任何绕过手段**（不轮换 Key、不伪造 `appname`、不代理他人配额）。
- 请自行阅读并遵守[高德开放平台服务条款](https://lbs.amap.com/)与[流量限制说明](https://lbs.amap.com/api/webservice/guide/tools/flowlevel)。
