## 1. 一句话定位

**如何让 Agent 可靠地完成一次用户指定的 POI 数据采集任务。**

- **一次**——有边界。单元数 = 关键词数 × 地区数，跑之前就能算出请求量；不做定时任务、不做队列、不做常驻爬虫。
- **可靠**——不静默丢、不静默失败。翻到 0 条才停；撞到返回量天花板必须明说；`status`/`infocode` 分三档处置；字段统一归一化。
- **Agent**——调用方而非实现方。`SKILL.md` 是契约，`--report-json` 是回执，退出码 `0/2/3` 是分流信号。

所以本项目的产物不是一个「能跑的 Python 脚本」，而是**一个能让 Agent 不犯错的接口**。

形态：**一个 Agent Skill**。仓库根目录就是技能目录——`SKILL.md` 是门面，`scripts/` 是引擎（Python 标准库，零三方依赖），`references/` 是附属文档。装进技能目录即被自然语言触发；不装 Agent 也能直接当命令行工具用，两条路径共用同一套代码。

## 2. 设计取舍

**只用一个接口：`v3/place/text`。** 早期方案是「v5 搜索拿名单 + `v3/place/detail` 逐条补电话」，实测 v5 的 `show_fields=business` **完全不含 `tel`**（0/25），`v3/place/detail` 也**补不出**（2 条均返回 `[]`），而 `v3/place/text` + `extensions=all` 本身就带 `tel`（23/25，92%）。所以砍掉整个补全环节：**一个接口拿全 19 个字段，200 条名单的请求量从 208 次降到约 10 次。**

**只做 POI 搜索。** 地理编码、路线规划、行政区划查询都不在第一版范围内。通用化不等于把高德 API 全塞进来——先把「关键词 + 地区 → 表格」这一条链路做扎实。

**三个必须内建的东西：**

| 问题 | 不做的后果 |
|---|---|
| 解析 `status`/`infocode` | 高德错误也返回 **HTTP 200**，只看 HTTP 码会把「key 失效」当成「查无结果」 |
| 空值归一化 | 空字段返回 JSON 数组 `[]`，不处理就会在表格里出现字面量 `[]` |
| 机器可读运行报告 | Agent 只能靠匹配 stdout 里的符号判断成败，无法可靠分流话术 |

## 3. 已验证的 API 事实

真实 key 实测，2026-11-05 至 11-07，累计约 170 次请求。**完整记录（含证据强度、已被推翻的结论、未验证项）在 [`references/api-notes.md`](references/api-notes.md)**，这里只列影响使用的部分。

| 项 | 结论 |
|---|---|
| 返回态 | 错误也返回 **HTTP 200**，真正的错误在 `status` / `infocode` |
| `tel` | `v3/place/text` + `extensions=all` **直接带电话**；v5 不带，`v3/place/detail` 补不出 |
| 翻页 | 正常，页间零重叠；同一查询重复调用**结果与顺序完全一致** → 去重可行 |
| **返回量天花板** | **约 200~225 条，且不固定**，随 `offset` 与查询本身漂移，之后返回空页 |
| `count` | **不可信**。海口 `count=551` 只取到 225，只能当「这里数据多」的弱提示 |
| 空字段 | 49 个字段中 25 个空值返回 JSON 数组 `[]`，不是 `""` |
| `offset` | 文档写 1~25，实测 50 也接受（本项目不依赖，固定 25） |
| 省级查询 | `city=海南省` 可用，返回跨市结果 |

### 3.1 地区参数：区县必须用 adcode

| 输入形态 | 处理 |
|---|---|
| 省名 / 城市名（`海南省` / `海口市`） | 直接用 |
| 6 位 adcode（`460106`） | 直接用，**区县查询的唯一可靠方式**，且是该市结果的子集 |
| 区县名（`龙华区`） | **直接拒绝**。实测被静默解析成**深圳**的龙华区，返回错误地区的数据 |
| 其他 / 模糊 | 报错并提示给城市名或 adcode，**不猜** |

> 转 adcode 需要地理编码接口，属暂不做的范围，用户可自行查 adcode 表。

### 3.2 天花板在哪里

第一版把「200 条硬上限」写成了结论，**复测发现是错的**：

| 查询 | offset | 取到条数 | 之后 |
|---|---|---|---|
| 汽修厂 @ 海口市 | 25 / 20 / 10 | **225 / 220 / 210** | 分别 p10 / p12 / p22 空 |
| 汽修厂 @ 成都市 | 25 / 10 | **200 / 200** | p9 / p21 空 |
| 汽修厂 @ 文昌市 | 25 | **106** | count=108，数据本身少 |

三条结论：

1. **不存在「第 201 条一定空」这条规则**——天花板随 `offset` 和查询本身漂移。
2. **不能靠页数判断到底**。唯一可靠的终止信号是「本页返回 0 条」。
3. **`count` 与可取得量无关**，不能参与算页数，也不能当完整性依据。

> 因此触顶判定写成 `raw >= 200` 的**启发式警告**，不是协议断言。它可能误报（数据恰好 200 但确实取全），但不会漏报。
> 曾试过追加 `count > raw` 作为第二判据，**已回退**：文昌 count=108 / 实得 106 只是数据本身少，却被判成触顶，导致退出码永远是 2。

### 3.2.1 切分查询范围能显著提高召回

天花板是按「查询」算的，所以**换个更窄的范围就等于换一个新的窗口**。实测（关键词「汽修厂」，`offset=25`）：

| 查询 | count | 去重条数 |
|---|---|---|
| 海口市整城 | 547 | **223**（触顶） |
| 460105 秀英区 / 460106 龙华区 / 460107 琼山区 / 460108 美兰区 | 200 / 163 / 99 / 123 | 192 / 157 / 92 / 115 |
| 四区并集 | — | **556** |

**整城漏掉 333 条，占四区并集的 60%。** 这就是触顶后建议「换更细行政区」的实测依据。

矩形切分（`v3/place/polygon`）同样成立：整矩形 195 条，四分后并集 386 条（约 1.98 倍）；且最大那一格自己仍触顶（count=503），说明**拆分必须递归到子网格不再触顶为止**，切一次不够。

这不叫「突破上限」：平台限制的是单次查询的翻页深度，不是账号总取量。把过大的查询拆成多个合法查询是推荐做法，但**不自动执行**——请求量成倍增长，必须用户知情同意。

## 4. 怎么用

仓库根目录 = 技能目录，同时也是可以直接敲命令的脚本目录。两条路径共用同一套代码，没有第二份实现。

| 你的情况 | 走哪条 |
|---|---|
| 有 DSH / Claude / 其它支持 skill 的 Agent | §4.1 装成技能，之后说一句话就行 |
| 只想在终端跑一下 | §4.2 直接敲命令 |
| 想改逻辑 | §8 分层结构，每层都能单独 import 测试 |

**禁止**让 AI 直接拼 HTTP 请求——不可复现、参数易错、无法统一限速和错误处理。**不做 GUI**——参数是自然语言组合（多城市、只要带电话的、按区分文件），GUI 无法穷举。

### 4.1 主要用法：装成 Agent Skill

**环境要求**：Python 3.6+（开发与测试在 3.8 上完成；只用到标准库，无需 `pip install`。`-f xlsx` 需要 `openpyxl`，不装会自动降级成 CSV）。

```bash
git clone https://github.com/<你的账号>/amap-poi-collector-skill.git
cd amap-poi-collector-skill

# 1. 配 key（三选一，推荐环境变量）
export AMAP_KEY=你的32位key                 # 或者：
cp config.example.json config.json          # 然后填进去

# 2. 把整个仓库挂进技能目录，目录名必须与 SKILL.md 里的 name 完全一致
ln -s "$PWD" ~/.dsh/skills/amap-poi-collector-skill      # Linux / macOS
```

Windows（在 cmd 里执行；用 `/J` 建目录联接，不需要管理员权限）：

```bat
mklink /J "%USERPROFILE%\.dsh\skills\amap-poi-collector-skill" "C:\path\to\amap-poi-collector-skill"
```

> 也可以直接把仓库克隆到 `~/.dsh/skills/amap-poi-collector-skill`，省掉建链接这一步。

装好后在 Agent 里说「帮我抓海口市的汽修厂名单」。Agent 会读 `SKILL.md`：追问关键词和地区 → `--dry-run` 报预算 → 等你点头 → 带 `--yes --report-json` 正式跑 → 按退出码 `0/2/3` 分流汇报。

**Skill 只是门面，不复制任何采集逻辑。** 换到另一个 Agent 平台只需调整 `SKILL.md` 的措辞，`scripts/amap_poi/` 一行都不用动。

### 4.2 也可以直接当命令行工具

```bash
py scripts/collect.py -k 汽修厂 -r 海口市 --dry-run          # 先看计划，不发请求
py scripts/collect.py -k 汽修厂 -r 海口市 --yes --report-json output/report.json
```

Windows 上 `py` 是 Python 启动器；其他平台用 `python3`。`scripts/collect.py` 会把同目录加入 `sys.path`，**不需要 `pip install -e .`**，也不需要 `setup.py` / `pyproject.toml`——这是技能目录该有的样子。

跑完会得到 `output/amap_poi_<时间戳>.csv`（19 列，UTF-8 BOM，双击就能用 Excel 打开）和 `output/report.json`（机器可读摘要，见 §6.1）。`output/` 已在 `.gitignore` 中（产物含真实商户电话，永不入库）。

三种格式装的是同一批数据，区别只在容器：

| `-f` | 内容 | 备注 |
|---|---|---|
| `csv`（默认） | 19 列，`utf-8-sig`，双击不乱码 | 给 Excel / WPS / 数透用 |
| `json` | `records` + `params` + `totals` + `units` + `errors` + `hit_cap_units` | 给程序读，能判定「这次完不完整」 |
| `xlsx` | `POI`（冻结首行、列宽已调）+ `运行摘要` 两个 sheet | 需要 `openpyxl` |

`xlsx` 在没装 `openpyxl` 时会**自动降级成同名 `.csv` 并返回那个路径**，不抛异常——所以判断产物要以 `--report-json` 里的 `outputs` 为准，不要按 `-o` 猜。

可选：多关键词 `-k A -k B`、多地区 `-r 海口市 -r 460106`。

> **工作目录提醒**：`scripts/collect.py` 里的 `scripts/` 是相对**当前工作目录**的。在别的目录执行请用绝对路径。key 不受影响——`config.json` 找不到时会回退到技能目录再找一次。

## 5. 参数设计

### 5.1 查询单元（基本单位）

一个**查询单元** = 1 关键词 × 1 地区。批量运行 = 多个单元顺序执行。

```
单元数 = 关键词数 × 地区数
本次请求数预估 = 单元数 × 10        （offset=25：约 9 页有数据 + 1 页空页收尾）
```

请求数是乘法增长的，这是本项目唯一需要向用户解释的成本模型。

> 预估值只用于「告诉用户大概要花多少次」，**不作为硬刹车**。实测不同城市结束页数不同（海口 9 页、成都 8 页），把预估当上限会砍掉正常的收尾空页请求，误报「已达请求上限」。真正的防跑飞是每个单元内部的页数保险丝（`200 // offset + 6` 页）。

### 5.2 参数表

只有两个必填，其余全部有默认值。普通用户不该被要求理解配置文件。

| 参数 | 必填 | 说明 | 默认 |
|---|---|---|---|
| 关键词 | ✅ | 找什么，可多个（`-k 汽修厂 -k 汽车维修`） | 无 |
| 地区 | ✅ | 城市名 / 省名 / **区县 adcode（6 位）** | 无 |
| 数量上限 | ❌ | 本次总条数上限，**默认不限**。单查询本身约 200~225 条就到顶，通常没必要设 | 不限 |
| 输出字段 | ❌ | 固定 19 列全字段（名称/电话/地址/分类/经纬度/评分/营业时间…） | 全字段 |
| 输出格式 | ❌ | `csv` / `json` / `xlsx` | csv |

「补电话」这个参数**不存在**——单接口方案下 v3 自带 `tel`，不需要问。

### 5.3 地区参数的硬规则

见 §3.1。补充一条：转 adcode 需要地理编码接口，属暂不做的范围，因此 MVP 对区县名是**拒绝并提示**，不自动转换。

### 5.4 去重与命中记录

按 `poi_id` 全局去重（实测同查询结果确定、id 稳定）。同一 POI 被多个关键词命中时，`命中关键词` 列合并为 `汽修厂;汽车维修`，不丢信息。

## 6. 必须内建的行为

| # | 行为 | 原因 |
|---|---|---|
| 1 | **翻到返回 0 条为止** | `count` 不可信、结束页因城市而异，唯一可靠的终止信号是空页 |
| 2 | **疑似触顶 → 警告而非自动拆** | 自动拆让请求量不可预测，对不懂配额的用户是灾难 |
| 3 | **`infocode` 三档处置** | `fatal` 立即中止 / `retry` 指数退避 / `skip` 跳过当前单元；未知码按 `skip`，不静默当成功 |
| 4 | **结果体检** | 跑完汇报条数、电话空缺率、是否触发错误码，不能只说「完成」 |
| 5 | **key 获取顺序** | `AMAP_KEY` → `config.json` → 提示粘贴；仓库内只放 `config.example.json` |
| 6 | **xlsx 优雅降级** | 未装 `openpyxl` 时提示一句并回落 CSV，不允许抛 traceback |
| 7 | **空值归一化** | `[]`/`None` → `""`；电话多值（`0898-00000000;13800000000`）保留原串，不拆列 |
| 8 | **预算器 + 硬刹车** | 执行前打印「单元数 × 预计请求数」并要求 `--yes`；`--max-requests` 触达即停并如实报告停在第几单元 |

错误码完整对照见 [`references/error-codes.md`](references/error-codes.md)。

### 6.1 运行报告契约（Skill 层依赖它，不能只有 stdout 文本）

`--report-json <path>` 输出机器可读摘要，字段固定：

```json
{
  "tool_version": "0.1.0",
  "started_at": "...", "finished_at": "...",
  "params": {"keywords": [], "regions": [], "max_records": 0, "format": "csv",
             "max_requests": 0},
  "units": [
    {"keyword": "汽修厂", "region": "海口市", "status": "ok", "requests": 10,
     "raw": 225, "new": 200, "pages": 10, "hit_cap": true, "count_hint": 551,
     "infocodes": {"10000": 10},
     "note": "疑似触顶：取满 225 条（该词在本地实际有 551 条），实际数据更多"}
  ],
  "totals": {"requests": 10, "raw": 225, "unique": 200, "tel_empty_rate": 0.195},
  "stopped_early": false, "stop_reason": "",
  "hit_cap_units": [{"keyword": "汽修厂", "region": "海口市", "raw": 225}],
  "errors": [],
  "outputs": {"csv": "output/xxx.csv", "report": ".../report.json"},
  "exit_code": 2
}
```

`status` 取值：`ok`（翻到空页正常结束）/ `partial`（被条数或请求上限截断、或撞上页数保险丝）/ `failed`（该单元请求失败）。

**退出码语义**：

| 码 | 含义 | Skill 应做什么 |
|---|---|---|
| `0` | 全部单元成功、无触顶 | 直接汇报结果 |
| `2` | 部分单元失败，或存在触顶 | 汇报结果 + 明确提示数据可能不完整 |
| `3` | key 无效 / 配额耗尽等致命错误 | 引导修复 key 或次日再试，不把半成品当「完成」展示 |

有了退出码 + report，`SKILL.md` 才能写成「按码分流话术」，而不是靠匹配 `⚠` 字符。

## 7. 明确不做

- ❌ GUI
- ❌ 商家真实性核验（属另一个业务 skill，与本项目无关）

- ❌ 百度 / 腾讯 / 企查查等其他数据源

## 8. 目录结构

仓库根目录**就是技能目录**（能直接 `ln -s` / `mklink` 到 `~/.dsh/skills/`），没有 `src/`、没有 `setup.py`、没有打包配置——少一层结构，Agent 少一个找不到文件的理由。

```
amap-poi-collector-skill/      # ← 技能目录，目录名必须与 SKILL.md 的 name 一致
├── SKILL.md                   # 门面：Agent 读它决定怎么问、怎么跑、怎么汇报
├── README.md                  # 本文件
├── SECURITY.md                # Key 泄漏处置、issue 里别贴什么
├── LICENSE  .gitignore  config.example.json
├── scripts/
│   ├── collect.py             # 单行入口：python scripts/collect.py ...
│   ├── amap_poi/              # 引擎：cli / client / collect / export / normalize / report
│   └── tests/                 # 与代码同住，pytest scripts/tests -q
├── references/                # SKILL.md 的附属文档：api-notes / error-codes / key-setup
└── samples/sample.csv         # 人工构造的假数据（不从真实数据抽样）
```

分层原则：`client` 只管 HTTP 与错误码，`normalize` 只管字段形状，`collect` 只管编排，`export` 只管落盘，`cli` 只管参数与退出码。**每一层都能单独 import 测试，不需要网络。**

`py -m pytest scripts/tests -q` → **207 passed**，全程不发任何网络请求（测试里的 API 响应是内联的假 dict，没有单独的 `fixtures/` 目录）。

## 9. 设计来源：一次业务脚本的重构

本项目脱胎于一个**业务专用的商户采集脚本**——在那里验证了接口选型和大部分踩坑，但业务口径、打分规则、多数据源占位代码都没有带过来。本节保留，是因为「哪些经验值得带走、哪些必须扔掉」对同类项目有用。

| 带走的 | 没带走的（原因） |
|---|---|
| key 申请与「必须选 Web服务」→ `references/key-setup.md` | 客户 A/B/C/D 分级、供应商适配度、开发优先级（业务口径） |
| v3 带 tel / v5 不带 / detail 补不出 → §2 与 api-notes | 百度 / 腾讯 / 企查查分支（从未实测的占位代码） |
| `utf-8-sig`（Excel 双击不乱码） | `v3/place/detail` 补电话流程（实测补不出） |
| 经纬度拆分、`pname` 兜底、`[]` 归一化 → `normalize.py` | 断点续跑 + `.progress.json`（MVP 不需要，格式不值继承） |
| | 「到量就 break 整个循环」的终止逻辑 |

> 原脚本产出过 26 个 CSV、全部精确 200 条，另有 6 个关键词从未执行——就是最后那条 bug 的直接后果。这也是本项目坚持「每个查询单元独立结算、触顶只警告不臆断」的由来。

## 10. 与高德平台 `amap-lbs-skill` 的关系

高德开放平台在 GitHub 上的组织 [`AMap-Web`](https://github.com/AMap-Web) 维护了 [`amap-lbs-skill`](https://github.com/AMap-Web/amap-lbs-skill)（MIT，Node.js）。两者**不是竞争关系，用途层级不同**：

| | 高德平台 `amap-lbs-skill` | 本项目 |
|---|---|---|
| 定位 | 地图能力的**对话入口**：问一句、看一眼、给个链接 | **批量采集工具**：跑一次、落一份文件、可核对 |
| 运行时 | Node.js + axios | Python 3 标准库（仅 xlsx 需 openpyxl） |
| 覆盖能力 | POI 搜索 / 周边 / 路径规划 / 旅游规划 / 热力图 | 只做 POI 搜索 + 导出 |
| 分页 | 一次一页，打印「第 x/y 页」让用户自己再敲一条命令 | 翻到返回 0 条为止，自动分页 |
| 去重 / 多关键词 | 无 | 按 `poi_id` 去重，命中关键词合并 |
| 输出 | 终端 `console.log` | CSV / JSON / XLSX + 运行报告 + 退出码 |

**可以并用**：先用本项目把名单落成表格，再用 `amap-lbs-skill` 做地图可视化或路径规划。

**为什么没做成它的延伸**：它是 Node 运行时、返回体是给人看的终端文本、接口契约随版本演进，把 Python 工具挂在它上面等于同时背两套运行时和两份维护风险。本项目只共用同一套平台 API，不共用代码。

**一个对采集场景有意义的差异**：`amap-lbs-skill` 用 `v5/place/text` 并以 `Math.ceil(count / offset)` 推算总页数；按本项目在 v3 上的实测，`count` 与实际可取得量并不一致（海口 `count=551`、实际 225 条）。交互场景下这样提示无害，但**批量采集时不能据此判断数据是否完整**——这是本项目坚持「翻到空页为止 + 如实报告」的原因。v5 的返回量上限是否与 v3 一致，本项目**未验证**。

## 11. 待定 / 下一步

**MVP 不做**：断点续跑（`--resume`）、v5 降级路径、地理编码、路线规划。但 `client.py` 的请求函数保持单一入口，为将来切 v5 留口。

**v0.2 候选**（按收益排序，尚未实现）：

1. `--types`（POI 类型编码，如 `050000` 汽车服务）：`v3/place/text` 原生参数，只改 `client._build_url` 加一个可选字段，能显著降低「汽修厂」被「汽车销售」污染的比例。
2. XLSX 多 sheet 按城市切分（当前 XLSX 只有 `POI` + `运行摘要` 两个 sheet）。
3. **递归切分（`--split-adcode` / `--split-bbox`）**：触顶时按 adcode 或矩形四分，递归到子区域不再触顶为止。思路来自 [AMapPoi](https://github.com/Civitasv/AMapPoi)，实测能把召回量提到近 2 倍（见 §3.2.1）。**未实现的原因**：请求量不可预测（一个城市可能拆成几十个子任务），对不懂配额的用户风险太大；要做必须先打印完整计划并要求显式确认。
4. 输出与高德官方热力图页面兼容的数据格式——**需先实测**官方页面的入参格式，未验证前不承诺。

不做：周边搜索（`location` + `radius`）。圆形区域内可返回量更少，会更快撞上返回量限制，在批量采集场景收益不如 `--types`。

## 12. 合规与安全提示

这一节不是法律意见，但使用前请逐条读完。

**关于 Key**

- 仓库里**只有** `config.example.json`（占位符）。`config.json`、`.env`、`*.key` 均在 `.gitignore` 中。
- 不要把 Key 写进命令行参数、issue、截图或提交记录；发现泄漏请立刻到控制台**删除该 Key**（改 IP 白名单不够）。
- 不要共用、转售或分发他人 Key。本工具不提供任何「免 Key」模式，这是有意为之。

**关于采集到的数据**

- POI 结果里的**商户名称、联系电话、地址**属于个人信息 / 商业信息，受《个人信息保护法》《数据安全法》等约束。本项目只负责「按你给的参数取回平台公开返回的内容」，**不判断你拿去做什么，也不为你的用途背书**。
- 明确不建议、也不支持的用途：未经同意的电话营销与短信推送、转售或再分发数据集、与数据主体无关的批量建档、绕过平台配额的大规模抓取。
- 公开演示、写文章、提 issue 时，**不要贴真实采集结果**；本项目 `samples/sample.csv` 是人工编造的假数据，可直接引用。

**关于平台规则**

- 请自行阅读并遵守[高德开放平台服务条款](https://lbs.amap.com/)与[流量限制说明](https://lbs.amap.com/api/webservice/guide/tools/flowlevel)。
- 本项目遵循平台的产品约束：单次查询返回量由平台决定（实测约 200~225 条），工具只做「翻到没有为止 + 如实报告」，**不实现任何绕过手段**。
- 请勿修改 `appname` 等标识参数去冒充其他应用。本项目不使用高德官方 Logo，也不声称官方身份（见开头[免责声明](#免责声明)）。

**发现问题怎么报**

- Key 泄漏处置、提 issue 时该打码什么，见 [SECURITY.md](SECURITY.md)。
