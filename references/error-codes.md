# 高德错误码处置

高德出错时 **HTTP 状态码仍然是 200**，必须在响应体的 `status` / `infocode` 里判断。
只看 HTTP 状态码的实现会在 key 失效时「返回 0 条并标记完成」——这是本项目必须解析
`status`/`infocode` 的直接原因。

代码位置：`scripts/amap_poi/client.py` 的 `FATAL_CODES` / `RETRY_CODES` / `SKIP_CODES`，
分类函数是 `classify(infocode)`，取值 `fatal` / `retry` / `skip`。

> **口径来源**：码值与含义照抄高德官方「错误码说明」
> （<https://lbs.amap.com/api/webservice/guide/tools/info>，最后更新 2022-10-12，2026-11-07 取）。
> 本项目**只实测过 `10000`、`10004`、`10009`** 三个码，其余是按文档推断的分类。
> 表格里的「未实测」标记不能省——分类错了会让 Agent 做错误的处置。

---

## 三种处置

| 分类 | 含义 | 行为 |
|---|---|---|
| `fatal` | 继续跑只会白烧配额或一直失败 | **立即中止整个运行**，退出码 `3` |
| `retry` | 频率类限制，等一下大概率能过 | 指数退避重试，最多 3 次（1/2/4/8 秒） |
| `skip` | 参数或数据范围问题，重试也不会变 | 跳过当前**查询单元**，继续下一个，退出码 `2` |

未知 infocode 一律按 `skip` 处理——宁可少跑一个单元，也不静默当成成功。

---

## fatal（中止）

| infocode | 官方含义 | 用户该做什么 | 实测 |
|---|---|---|---|
| `10001` | key 不正确或过期 | 重新申请「Web服务」类型的 key | 未实测 |
| `10002` | 没有权限使用该服务，**或接口路径拼写错误** | 检查控制台的服务授权 | 未实测 |
| `10003` | 当日访问量已超限 | 次日 0:00 自动解封 | 未实测 |
| `10005` | IP 白名单校验失败 | 检查 key 是否绑定了服务器 IP | 未实测 |
| `10006` | 绑定域名无效 | Web 服务 key 不应绑定域名 | 未实测 |
| `10007` | 数字签名未通过 | 检查 key 是否开启了数字签名 | 未实测 |
| `10009` | **key 与绑定平台不符** | 申请的是 JS API key，需要「Web服务」 | **已实测** |
| `10010` | IP 访问超限且**已被封停** | 无法自动恢复，需提工单 | 未实测 |
| `10011` | **该服务不支持 HTTPS** | 需提工单申请 | 未实测 |
| `10012` | **权限不足，服务被拒绝** | 检查该 key 是否开通了「搜索 POI」 | 未实测 |
| `10013` | key 已被删除 | 重新申请 | 未实测 |
| `10026` | **账号处于被封禁状态** | 需提工单申诉 | 未实测 |
| `10041` | 请求的接口权限**过期**（不是余额） | 联系高德续期 | 未实测 |
| `10044` | 账号维度日调用量超限 | 次日再试或换账号 | 未实测 |
| `10045` | 账号维度**海外**服务日调用量超限 | 次日再试 | 未实测 |
| `40000` | 所购买服务的余额耗尽 | 充值 | 未实测 |
| `40002` | 所购买的服务已到期 | 续费 | 未实测 |
| `40003` | 所购买的**海外**服务余额耗尽 | 充值 | 未实测 |

> `10009` 是最常见的坑：高德控制台默认展示 JS API，用户复制了错误的 key。
> 报错话术必须点名「Web服务」，否则用户会反复试同一个 key。
>
> `10010` 与 `10004` 别混：`10004` 是「这一分钟太频繁，下一分钟自动解封」，
> 可以退避重试；`10010` 是「IP 已被封停，无法自动恢复」，重试只会一直失败。
>
> `10011` / `10012` 的官方含义容易被名字误导：它们**不是**「参数错误」，
> 而是「不支持 HTTPS」和「权限不足」，所以归到 `fatal` 而不是 `skip`。

## retry（退避重试）

| infocode | 官方含义 | 实测 |
|---|---|---|
| `10004` | 单位时间内访问过于频繁（按分钟限流，自动解封） | **已实测**（把 `--interval` 调到 0.1 以下必现） |
| `10014` | 云图服务 QPS 超限 | 未实测 |
| `10015` | 受单机 QPS 限流（网关超时） | 未实测 |
| `10016` | 服务器负载过高 | 未实测 |
| `10017` | 所请求的资源不可用 | 未实测 |
| `10019` | 某个服务的**总** QPS 超限 | 未实测 |
| `10020` | 某个 **key** 对某个服务接口的 QPS 超限 | 未实测 |
| `10021` | **账号**对某个服务接口的 QPS 超限 | 未实测 |
| `10029` | 某个 key 的 QPS/调用量超出限制 | 未实测 |
| `300xx` | 引擎响应失败，官方只给了前缀（如 30001/32000/32203） | 未实测 |

`300xx` 按**前缀**匹配（5 位数字且以 `3` 开头），不是枚举表里的固定键。

本项目默认 `--interval 0.4`（2.5 QPS）串行请求，实测未触发过 `10004`。
如果用户把 `--interval` 调到 0.1 以下，`10004` 就会频繁出现。

## skip（跳过单元）

| infocode | 官方含义 | 实测 |
|---|---|---|
| `10008` | MD5 安全码未通过（仅 SDK 场景，Web 服务 key 不会触发） | 未实测 |
| `20000` | 请求参数非法，值未按规范填写 | 未实测 |
| `20001` | 缺少必填参数 | 未实测 |
| `20002` | 请求协议非法（例如只支持 GET 却用了 POST） | 未实测 |
| `20003` | 其他未知错误 | 未实测 |
| `20011` | **查询点在海外，但 key 没有海外地图权限** | 未实测 |
| `20012` | 查询内容存在非法字符 | 未实测 |
| `20800` | 规划点不在中国大陆陆地范围内 | 未实测 |

> 之前版本的文档把 `20011` 写成「查询不到数据或该区域不支持此服务」，那是错的。
> 官方含义是「点在海外但无海外权限」。POI 查不到数据时高德正常返回空 `pois` 数组，
> **不会**返回 `status=0`。

## 网络层错误

| 情况 | 分类 | 说明 |
|---|---|---|
| HTTP 5xx | `retry` | 服务端抖动，退避后大概率恢复 |
| HTTP 4xx | `skip` | 基本是配置问题，重试无意义 |
| 连接失败 / 超时 | `retry` | 本地网络 |
| 响应不是合法 JSON | `retry` | 可能被公司网关或代理拦截 |

---

## 退出码与错误码的对应

CLI 退出码由 `report.compute_exit_code()` 统一算：

```
3  ← 出现 fatal 错误（key/配额/授权/封禁）
2  ← 有单元 failed 或 partial，或有单元 hit_cap
0  ← 全部单元正常翻到空页
```

`skip` 错误不会直接变成退出码 3，只会让该单元 `status=failed`，整体退 `2`。
