# 高德 POI API 实测笔记

本文件只记录**亲手跑过**的结论，并明确分开「已验证」与「未验证」。
所有请求都是 `v3/place/text` + `extensions=all`，真实 key，2026-11-05 至 2026-11-07 累计约 170 次。

---

## 1. 已验证（可以直接依赖）

| 项 | 结论 | 证据强度 |
|---|---|---|
| 接口 | `GET https://restapi.amap.com/v3/place/text` | 多次成功 |
| 电话字段 | `extensions=all` 时**直接返回 `tel`**，覆盖率 23/25（92%） | 单次抽样 |
| `v5/place/text` | `show_fields=business` 下**完全不含 `tel`**（0/25） | 单次抽样 |
| `v3/place/detail` | 对 `tel` 为空的 POI **补不出电话**，2 条均返回 `[]` | 小样本 |
| 分页 | page1/page2 零重叠；同一查询重复调用**结果与顺序完全一致**（25/25 同序） | 重复两次对比 |
| `offset` | 文档写 1~25，**实测 50 也接受**（本项目不依赖，固定 25） | 单次 |
| 省级查询 | `city=海南省` 可用，返回跨市结果（海口/文昌/琼海/澄迈/临高） | 多次 |
| 区县 adcode | `city=460106` 精确返回海口市龙华区，且是海口市结果的子集（7/25 重叠） | 单次 |
| 区县名（中文） | `city=龙华区` **静默解析到广东省深圳市龙华区**，`citylimit=false` 时同样串区 → 不可用 | 两次一致 |
| `children` | 城市级查询下 `children=0` 与 `children=1` 结果**完全一致**（count 与 adname 集合均相同） | 单次对比 |
| 错误返回 | **HTTP 始终 200**，真正的错误在 `status` / `infocode` | 多次 |
| 空值形态 | 49 个 POI 字段中**25 个空值返回 JSON 数组 `[]`**，不是 `""` | 单次 25 条全量 |
| `tel` 形态 | 字符串；多号码用分号连接，如 `0898-00000000;13800000000` | 同上 |
| `biz_ext` | dict，含 `rating`（字符串 `"4.7"`）、`open_time`、`cost`（空时为 `[]`） | 同上 |
| 顶层键 | `status` / `info` / `infocode` / `count` / `pois` / `suggestion` | 同上 |

## 2. 已被复测推翻的结论（写在这里防止再犯）

> 第一版文档把下面这条写成了定论，**是错的**。

**❌ 错误结论**：「单查询硬上限恰好 200 条，第 9 页必定返回空。」

**✅ 实测真相**：天花板漂移在 200~225 之间，随 `offset` 与查询本身变化。

| 查询 | offset | 有效页 | 取到条数 | 之后 |
|---|---|---|---|---|
| 汽修厂 @ 海口市 | 25 | 9 页 | **225** | p10 空 |
| 汽修厂 @ 海口市 | 20 | 11 页 | **220** | p12 空 |
| 汽修厂 @ 海口市 | 10 | 21 页 | **210** | p22 空 |
| 汽修厂 @ 海口市（460106） | 25 | 7 页 | **164** | p8 空 |
| 汽修厂 @ 成都市 | 25 | 8 页 | **200** | p9 空 |
| 汽修厂 @ 成都市 | 10 | 20 页 | **200** | p21 空 |
| 汽修厂 @ 文昌市 | 25 | 5 页 | **106** | count=108，数据本身少 |

由此确立的两条硬规则：

1. **唯一可靠的终止信号是「本页返回 0 条」。** 不能按页数停（成都 offset=10 时 20 页空，
   海口 offset=10 时 21 页才空），也不能按 `count` 算页数。
2. **`count` 与可取得量无关。** 海口 count=551 / 实得 225；成都 count=572 / 实得 200。
   只能当「这里数据多」的弱提示。

因此代码里的触顶判定是 `raw >= 200` 的**启发式警告**，不是协议断言。
曾尝试追加 `count > raw` 作为第二判据，导致文昌（count=108 / 实得 106）被误判触顶、
退出码永远是 2，**已回退**。

### 切分查询范围能显著提高召回（2026-11-07 补测）

既然天花板是按「查询」算的，那么**换一个更窄的查询范围，就等于换一个新的 200 窗口**。
两次独立实验都证实了这一点。

**实验 A：同一城市，整城 vs 按 adcode 分 4 个区县**（`v3/place/text`，关键词「汽修厂」，offset=25）

| 查询 | count | 原始条数 | 去重条数 |
|---|---|---|---|
| 海口市（整城） | 547 | 225（触顶） | **223** |
| 460105 秀英区 | 200 | 198 | 192 |
| 460106 龙华区 | 163 | 160 | 157 |
| 460107 琼山区 | 99 | 92 | 92 |
| 460108 美兰区 | 123 | 116 | 115 |
| 四区并集 | — | — | **556** |

整城只拿到 223 条，四区并集 556 条，**整城漏掉 333 条（占并集的 60%）**。

**实验 B：矩形范围 vs 四分矩形**（`v3/place/polygon`，同一矩形：`110.15,20.10|110.75,19.55`）

| 查询 | count | 原始条数 | 去重条数 |
|---|---|---|---|
| 整矩形 | 579 | 200（触顶） | **195** |
| 左上 1/4（SW/SE/NW/NE 中最大） | 503 | 200（触顶） | 197 |
| 四格并集 | — | — | **386** |

四格并集是整矩形的 **1.98 倍**。注意左上 1/4 自己仍然触顶（count=503），
说明**切分必须递归到子网格 count 小于窗口为止**，切一次不够。

**结论**：这不是「绕过平台限制」，而是「把一个过大的查询拆成多个合法的查询」。
平台文档限制的是单次查询的翻页深度，不是账号总取量。本项目因此把
「换更细的行政区（6 位 adcode）」作为触顶后的**首选建议**，但**不自动拆**——
因为拆分会让请求量成倍增长，必须让用户知情。

### 与平台文档口径的差异（如实记录）

[搜索 POI 2.0 文档](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch) 原文：

> 目前搜索是不支持返回全量数据的，同请求参数翻页查询最多支持获取 200 条数据

两点说明：

- 这是**平台的产品说明**，本项目把它当作不可绕过的约束，不做任何规避实现。
- 我方在 v3 上实测到 225 条（海口 offset=25），与文档的「200」不完全一致。
  **不因此认为文档错误**——可能是 v5 与 v3 的窗口策略不同、可能是统计口径不同
  （分页窗口 vs 去重后条数）、也可能是短暂服务端差异。本项目**只把 `raw >= 200`
  当作「可能触顶」的提示**，不据此宣称任何精确上限。
- v5 是否同样漂移、漂移到哪，**未验证**。

## 3. 未验证（不要当成事实写进文档或代码）

- **天花板由什么决定**：服务端随机？按账号配额？按城市数据量？没有控制变量实验。
- **adcode 级查询是否同样有天花板**：**是**。460105 秀英区 count=200 / 实得 198，卡在窗口边缘
  （2026-11-07 补测）。但 460106 只取到 160（count=163），无法区分是数据本身少还是被截断。
- **限速阈值**：本项目固定 `--interval 0.4`（2.5 QPS）从未触发 `10004`，但高德真实 QPS
  上限未知，只验证了「0.4s 在这个 key 上没被打」。
- **`offset` 与服务端窗口的关系**：每次请求 `(page-1)*offset` 超过约 200 后很快返空，
  但边界不稳定，没有精确刻画。
- **`count` 的语义**：是「匹配总数」还是「可检索总数」，未知。
- **v5 降级路径**：未实现。若 v3 某天下线，`client.AmapClient._request` 是唯一改动点。
- **港澳台 / 境外**：高德 POI 的服务范围仅覆盖中国大陆。官方错误码表里 `20011` 是
  「查询点在海外但 key 无海外地图权限」、`20800` 是「规划点不在中国大陆陆地范围内」
  （后者主要用于路径规划）。**本项目的 text 搜索遇到境外地名时到底返回空结果还是报错，
  未实测**——两种情况的处置不同（前者退出码 0，后者退出码 2）。
- **`citylimit=false` 的跨城行为**：只测过区县名那个用例，其余未测。

## 4. 请求量与成本

```
单元数 = 关键词数 × 地区数
单单元请求数 ≈ 10（offset=25：约 9 页有数据 + 1 页空页收尾）
```

实测样本：

| 场景 | 单元数 | 请求数 | 去重条数 |
|---|---|---|---|
| 汽修厂 @ 海口市 | 1 | 10 | 223 |
| 汽修厂 @ 文昌市 | 1 | 6 | 106 |
| 汽修厂 + 汽车维修 × 海口市 + 460106 | 4 | 36 | 599（原始 785） |

请求数是**乘法**增长的，这是唯一需要向用户解释的成本模型。
`estimate_requests()` 的预估值只用于告知用户，**不作为硬刹车**（理由见 README §5.1）。
