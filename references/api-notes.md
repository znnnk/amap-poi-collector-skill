# 高德 POI API 实测笔记

本文件只记录**亲手跑过**的结论，并明确分开「已验证」与「未验证」。
请求以 `v3/place/text` + `extensions=all` 为主，另有少量 `v3/config/district`（见 §8），
真实 key，2026-11-05 至 2026-11-08 累计约 200 次。

---

## 2. 已被复测推翻的结论（写在这里防止再犯）

> 第一版文档把下面这条写成了定论，**是错的**。

**❌ 错误结论**：「单查询硬上限恰好 200 条，第 9 页必定返回空。」

**✅ 实测真相**：天花板漂移在 200~225 之间，随 `offset` 与查询本身变化。

| 查询 | offset | 有效页 | 取到条数 | 之后 |
|---|---|---|---|---|
| 汽修厂 @ 海口市 | 25 | 9 页 | **225** | p10 空 |
| 汽修厂 @ 海口市 | 20 | 11 页 | **220** | p12 空 |
| 汽修厂 @ 海口市 | 10 | 21 页 | **210** | p22 空 |
| 汽修厂 @ 海口市（460106） | 25 | 7 页 | **164** | p8 空 |
| 汽修厂 @ 成都市 | 25 | 8 页 | **200** | p9 空 |
| 汽修厂 @ 成都市 | 10 | 20 页 | **200** | p21 空 |
| 汽修厂 @ 文昌市 | 25 | 5 页 | **106** | count=108，数据本身少 |

由此确立的两条硬规则：

1. **唯一可靠的终止信号是「本页返回 0 条」。** 不能按页数停（成都 offset=10 时 20 页空，
   海口 offset=10 时 21 页才空），也不能按 `count` 算页数。
2. **`count` 与可取得量无关。** 海口 count=551 / 实得 225；成都 count=572 / 实得 200。
   只能当「这里数据多」的弱提示。

因此代码里的触顶判定是 `raw >= 200` 的**启发式警告**，不是协议断言。
曾尝试追加 `count > raw` 作为第二判据，导致文昌（count=108 / 实得 106）被误判触顶、
退出码永远是 2，**已回退**。

### 切分查询范围能显著提高召回（2026-11-07 补测）

既然天花板是按「查询」算的，那么**换一个更窄的查询范围，就等于换一个新的 200 窗口**。
两次独立实验都证实了这一点。

**实验 A：同一城市，整城 vs 按 adcode 分 4 个区县**（`v3/place/text`，关键词「汽修厂」，offset=25）

| 查询 | count | 原始条数 | 去重条数 |
|---|---|---|---|
| 海口市（整城） | 547 | 225（触顶） | **223** |
| 460105 秀英区 | 200 | 198 | 192 |
| 460106 龙华区 | 163 | 160 | 157 |
| 460107 琼山区 | 99 | 92 | 92 |
| 460108 美兰区 | 123 | 116 | 115 |
| 四区并集 | — | — | **556** |

整城只拿到 223 条，四区并集 556 条，**整城漏掉 333 条（占并集的 60%）**。

**实验 B：矩形范围 vs 四分矩形**（`v3/place/polygon`，同一矩形：`110.15,20.10|110.75,19.55`）

| 查询 | count | 原始条数 | 去重条数 |
|---|---|---|---|
| 整矩形 | 579 | 200（触顶） | **195** |
| 左上 1/4（SW/SE/NW/NE 中最大） | 503 | 200（触顶） | 197 |
| 四格并集 | — | — | **386** |

四格并集是整矩形的 **1.98 倍**。注意左上 1/4 自己仍然触顶（count=503），
说明**切分必须递归到子网格 count 小于窗口为止**，切一次不够。

**结论**：这不是「绕过平台限制」，而是「把一个过大的查询拆成多个合法的查询」。
平台文档限制的是单次查询的翻页深度，不是账号总取量。本项目因此把
「换更细的行政区（6 位 adcode）」作为触顶后的**首选建议**，但**不自动拆**——
因为拆分会让请求量成倍增长，必须让用户知情。

### 与平台文档口径的差异（如实记录）

[搜索 POI 2.0 文档](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch) 原文：

> 目前搜索是不支持返回全量数据的，同请求参数翻页查询最多支持获取 200 条数据

两点说明：

- 这是**平台的产品说明**，本项目把它当作不可绕过的约束，不做任何规避实现。
- 我方在 v3 上实测到 225 条（海口 offset=25），与文档的「200」不完全一致。
  **不因此认为文档错误**——可能是 v5 与 v3 的窗口策略不同、可能是统计口径不同
  （分页窗口 vs 去重后条数）、也可能是短暂服务端差异。本项目**只把 `raw >= 200`
  当作「可能触顶」的提示**，不据此宣称任何精确上限。
- v5 是否同样漂移、漂移到哪，**未验证**。

## 3. 未验证（不要当成事实写进文档或代码）

- **天花板由什么决定**：服务端随机？按账号配额？按城市数据量？没有控制变量实验。
- **限速阈值**：本项目固定 `--interval 0.4`（2.5 QPS）从未触发 `10004`，但高德真实 QPS
  上限未知，只验证了「0.4s 在这个 key 上没被打」。
- **`offset` 与服务端窗口的关系**：每次请求 `(page-1)*offset` 超过约 200 后很快返空，
  但边界不稳定，没有精确刻画。
- **`count` 的语义**：是「匹配总数」还是「可检索总数」，未知。
- **v5 降级路径**：未实现。若 v3 某天下线，`client.AmapClient._request` 是唯一改动点。
- **港澳台 / 境外**：高德 POI 的服务范围仅覆盖中国大陆。官方错误码表里 `20011` 是
  「查询点在海外但 key 无海外地图权限」、`20800` 是「规划点不在中国大陆陆地范围内」
  （后者主要用于路径规划）。**本项目的 text 搜索遇到境外地名时到底返回空结果还是报错，
  未实测**——两种情况的处置不同（前者退出码 0，后者退出码 2）。
- **`citylimit=false` 的跨城行为**：只测过区县名那个用例，其余未测。

## 4. 请求量与成本

```
单元数 = 关键词数 × 地区数
单单元请求数 ≈ 10（offset=25：约 9 页有数据 + 1 页空页收尾）
```

实测样本：

| 场景 | 单元数 | 请求数 | 去重条数 |
|---|---|---|---|
| 汽修厂 @ 海口市 | 1 | 10 | 223 |
| 汽修厂 @ 文昌市 | 1 | 6 | 106 |
| 汽修厂 + 汽车维修 × 海口市 + 460106 | 4 | 36 | 599（原始 785） |

请求数是**乘法**增长的，这是唯一需要向用户解释的成本模型。
`estimate_requests()` 的预估值只用于告知用户，**不作为硬刹车**——实测不同城市结束页数不同
（海口 9 页、成都 8 页），把预估当上限会砍掉正常的收尾空页请求，误报「已达请求上限」。
真正的防跑飞是每个单元内部的页数保险丝（`200 // offset + 6` 页）。

## 5. 未实现的能力（v0.2 候选，按收益排序）

1. **`--types`（POI 类型编码，如 `050000` 汽车服务）**：`v3/place/text` 的原生参数，
   只改 `client._build_url` 加一个可选字段，能显著降低「汽修厂」被「汽车销售 / 洗车」污染的比例。
2. **XLSX 多 sheet 按城市切分**：当前 XLSX 只有 `POI` + `运行摘要` 两个 sheet。
3. **递归切分（`--split-adcode` / `--split-bbox`）**：触顶时按 adcode 或矩形四分，递归到子区域
   不再触顶为止。思路来自 [AMapPoi](https://github.com/Civitasv/AMapPoi)，实测能把召回量提到
   近 2 倍（见本文 §2 的补测）。**未实现的原因**：请求量不可预测（一个城市可能拆成几十个
   子任务），对不懂配额的用户风险太大；要做必须先打印完整计划并要求显式确认。
4. **输出与高德官方热力图页面兼容的数据格式**：需先实测官方页面的入参格式，未验证前不承诺。

明确不做：**周边搜索**（`location` + `radius`）。圆形区域内可返回量更少，会更快撞上返回量
限制，在批量采集场景收益不如 `--types`。另：断点续跑（`--resume`）、v5 降级路径、
地理编码（地址 ⇄ 经纬度，与行政区划查询是两回事，后者已实现见 §8）、
路线规划均不在 MVP 范围；`client.AmapClient._request` 保持单一入口，为将来切 v5 留口。

## 6. 与高德平台 `amap-lbs-skill` 的实现差异（备查）

高德开放平台在 GitHub 组织 [`AMap-Web`](https://github.com/AMap-Web) 维护了
[`amap-lbs-skill`](https://github.com/AMap-Web/amap-lbs-skill)（MIT，Node.js）。
两者不是竞争关系，用途层级不同：官方那个是「地图能力的对话入口」，本项目是「批量采集工具」。

只在实现层面记录三处差异，供后来者判断要不要参考：

| 项 | `amap-lbs-skill` | 本项目 |
|---|---|---|
| 分页 | 一次一页，打印「第 x/y 页」让用户自己再敲一条命令 | 翻到返回 0 条为止，自动分页 |
| 页数推算 | `Math.ceil(count / offset)` | **不推算**——`count` 与可取得量不一致（见本文 §2） |
| 请求标识 | 每次调用前发埋点请求，且强制追加 `appname` | 不发埋点、不伪造 `appname` |

`Math.ceil(count / offset)` 在交互场景下无害（只是提示语不准），但批量采集时
会让人误以为数据完整——这正是本项目坚持「翻到空页为止 + 如实报告」的原因。
v5 的返回量上限是否与 v3 一致，**未验证**。

## 7. 设计来源（仅备查）

本项目脱胎于一个业务专用的商户采集脚本——在那里验证了接口选型和大部分踩坑，但业务口径、
打分规则、多数据源占位代码都没有带过来。

| 带走的 | 没带走的（原因） |
|---|---|
| key 申请与「必须选 Web服务」 | 客户 A/B/C/D 分级、供应商适配度、开发优先级（业务口径） |
| v3 带 tel / v5 不带 / detail 补不出 | 百度 / 腾讯 / 企查查分支（从未实测的占位代码） |
| `utf-8-sig`（Excel 双击不乱码） | `v3/place/detail` 补电话流程（实测补不出） |
| 经纬度拆分、`pname` 兜底、`[]` 归一化 | 断点续跑 + `.progress.json`（格式不值继承） |
| | 「到量就 break 整个循环」的终止逻辑 |

> 原脚本产出过 26 个 CSV、全部精确 200 条，另有 6 个关键词从未执行——就是最后那条 bug 的
> 直接后果。这也是本项目坚持「每个查询单元独立结算、触顶只警告不臆断」的由来。

## 8. `v3/config/district` 实测（2026-11-08，区县名解析用）

`scripts/amap_poi/regions.py` 的全部依据。目的：让用户能直接说「龙华区」，而不用自己去查 adcode。

| 项 | 结论 | 证据强度 |
|---|---|---|
| 接口 | `GET https://restapi.amap.com/v3/config/district`，参数 `keywords=中国&subdistrict=3&extensions=base` | 多次 |
| 一次拿全量 | **1 次请求**返回 488 KB，扁平化后 34 省 + 390 地级 + 3213 区县 = **3637 节点** | 3 次一致 |
| `subdistrict` | `=2` 只到省+市（450 节点），不够；`=3` 到区县；`=4` 会带 street（不需要） | 各 1 次 |
| 根节点 | `name=中华人民共和国`、`level=country`、`adcode=100000`，本身不是检索单位，**但必须下探** | 多次 |
| street 级 | 与父级城市**共用同一 adcode**（东莞 441900 下 32 个街道全为 441900），保留会让 adcode 反查有歧义 | 1 次 |
| 区县重名 | 3548 个不同区县名中，**50 个重名，涉及 116 个区县**（`鼓楼区` 4 个、`新华区` 3 个、`朝阳区` 2 个、`龙华区` 2 个） | 全量统计 |
| `filter` 参数 | **完全无效**：`filter=citycode:0898` / `filter=adcode:460100` / `filter=citycode:0755` 都返回同样 2 条「龙华区」，不消歧 | 3 次一致 |
| 复合名查询 | `keywords=海口市龙华区` / `深圳市龙华区` / `海南龙华区` 全部 `count=0` → **官方接口无法消歧，只能本地索引** | 3 次一致 |
| adcode 反查 | `keywords=460106` 返回龙华区 | 1 次 |
| 无区县层的城市 | **36 个**：东莞 441900、中山 442000、济源 419001、仙桃/潜江/天门/神农架、新疆兵团各市、海南文昌/儋州/万宁/东方等、嘉峪关 | 全量统计 |
| 直辖市结构 | `北京市`(province) → `北京城区`(city, 110100) → 16 区；重庆有两个 city（500100 城区 / 500200 郊县） | 1 次 |
| 省级 adcode 可用于 POI | `city=460000` → `count=599`，省级 adcode 当地区参数有效 | 1 次 |
| 响应体积 | 缓存成紧凑 JSON 179 KB；全量 CSV 4065 行 / 114 KB | 实测 |
| **网页工具不可爬** | `lbs.amap.com/tools/picker` 是 JS 渲染，HTML 83 KB 里 `adcode` 命中 **0 次** → 「让 Agent 自己去网页查」这条路走不通 | 1 次 |

由此确立的设计：**本地索引 + 拒绝猜**。`find()` 依次尝试 6 位 adcode → 全名 → 复合名递归下降
→ 前缀 → 去后缀比较；返回多个即视为歧义，由调用方列出候选并要求用户改用 adcode。
行政区划缓存 30 天，**有缓存时不需要 key**（纯离线）；行政区划本身极少变动，过期后无 key 也允许继续用旧缓存。
